### 前置检查结果：比预期严重

文档里的核对 SQL 本来只想找「零星漏配价的模型」，实际跑出来是**整站都靠兜底**：

| 事实 | 数值 |
|---|---|
| 有渠道且在售的模型 | 4 个，全部走渠道 5「火山方舟」（type 45） |
| `options` 表总行数 | 5 行（`SystemName` / `LegacyAccessTokenRetireAt` / `checkin_setting.enabled` / `DemoSiteEnabled` / `SelfUseModeEnabled`） |
| `ModelRatio` / `CompletionRatio` / `ModelPrice` | **三个键都不存在**，价格表全靠代码内置默认值 |
| `SelfUseModeEnabled` | `true` —— 这是这 4 个模型唯一能计费的原因 |
| 4 个模型近 30 天调用 | 51 次，合计约 36 万 quota（真实业务，不是测试） |

即：**直接删自用模式 = 全站 0 个可用模型**。若按文档原方案「有内容就先补价」，补价这一步必须做完才能改代码。

### 处理方式：把隐式兜底变成显式配价

给这 4 个模型写入 `ModelRatio = 37.5`（与旧兜底值逐位一致），计费金额不变：

```sql
-- 执行前已备份：CREATE TABLE options_backup_20261020 AS SELECT * FROM options;
INSERT INTO options(key,value) VALUES ('ModelRatio',
  '{"deepseek-v4-1-flash-260910":37.5,"deepseek-v4-flash-ga-260731":37.5,
    "deepseek-v4-pro-ga-260813":37.5,"glm-5-3-flash-260828":37.5}')
ON CONFLICT (key) DO UPDATE SET value=EXCLUDED.value;
```

`common.OptionMap` / `modelRatioMap` 是**整体替换**语义（`LoadFromJsonStringWithCallback` 里 `make(map)`），所以写 4 个 = 价格表只剩 4 个。对本站是好事：价格页从此只显示自己在卖的模型，不再混着 225 条用不上的默认项。

**遗留**：37.5 是历史兜底值（约合 $75 / 1M tokens），明显不是真实成本价。运营需要按上游实际报价改成真值，改完计费才准；在那之前扣的是旧口径的额度。

原方案只写了 `controller/model.go` 的 `acceptUnsetRatioModel`，实际还有第二条路：`dto.UserSetting.AcceptUnsetRatioModel`（个人设置里的「接受未定价模型」开关），在 `price.go` 的预付和结算两处都能让未定价模型照常计费。**只删全局开关会留下这个后门**，两处一起删才真正关闭。

### 测试

原来有 2 个用例靠 `withSelfUseModeEnabled` 让未定价的 fixture 出现在列表里（测的是端点类型解析、token 分组快照，不是定价）。删除开关后它们按新规则被过滤，用例失败。

处理：新增 `withModelRatios(t, models...)` 辅助函数显式给 fixture 配价并注册 cleanup 还原，两个用例各补一行。这样测试不再依赖全局开关，语义也更明确——**要出现在列表里就必须有价**。
